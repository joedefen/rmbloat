# rmbloat audit (v0.8.5)

## Scope and method
- Reviewed all 16 modules in [`rmbloat/`](rmbloat) (~7,157 lines), [`pyproject.toml`](pyproject.toml), [`README.md`](README.md), [`BLURB.md`](BLURB.md), [`linter`](linter), and [`runner`](runner).
- Performed static review, `python3 -m py_compile rmbloat/*.py`, `pylint --errors-only`, and targeted behavioral probes for the highest-risk paths.
- Third-party runtime dependencies (`console_window`, `ruamel.yaml`, `send2trash`) are not installed in this checkout, so the curses UI was not exercised end-to-end. FFmpeg 7.1 is installed and was used for command-generation checks.
- The initial review performed no code modifications; applied fixes are recorded under “Resolved findings” at the end of this document.

## Overall assessment
The architecture is sensible: clear module boundaries, dataclass models, argv-list subprocess calls, a probe cache, a retry ladder, and a structured logger. However, several **user-facing paths are broken today**, and the file-replacement path has **data-loss risks** that contradict the README. The project also lacks automated tests/CI capable of catching these regressions.

# Critical findings

### C1. ✅ `rmbloat --logs` always crashes with `IndexError`
[`StructuredLogger.log_paths`](rmbloat/StructuredLogger.py:584) returns exactly one path, but [`main()`](rmbloat/rmbloat.py:1445) unconditionally accesses `files[1]`. Verified with a live logger: `log_paths` length is 1, `files[1]` raises `IndexError`. The README advertises this command at [`README.md:538`](README.md:538).

### C2. ✅ The documented quick-start command `rmbloat --chooser-tests` crashes
When no video file is supplied, [`main()`](rmbloat/rmbloat.py:1472) sets `show_test_encode=True`. [`FfmpegChooser.run_tests()`](rmbloat/FfmpegChooser.py:980) then builds an example using `input_file='input.mp4'`, and [`make_namespace()`](rmbloat/FfmpegChooser.py:534) raises `FileNotFoundError` because that file normally does not exist. `run_tests()` only catches `RuntimeError` and `KeyboardInterrupt`. Reproduced: `run_tests -> FileNotFoundError input_file does not exist: input.mp4`. This breaks the first command in the README’s Quick Start ([`README.md:19`](README.md:19)).

### C3. ✅ `--save-defaults` never saves the new values
[`IniManager.write()`](rmbloat/IniManager.py:139) iterates `self._default_values` and writes those constructor defaults, not the current `self.vals` attributes. [`main()`](rmbloat/rmbloat.py:1438) updates `ini.vals` and calls `ini.write()`, so the printed “new defaults” are not persisted. Reproduced: setting `vals.beta='CHANGED'` and calling `write()` still produced `beta = default`. This also means any INI schema mismatch rewrite silently resets user settings to constructor defaults. This is likely the most damaging configuration bug.

### C4. ✅ Any non-video, audio-only, or stale path crashes startup
[`ProbeCache._get_metadata_with_ffprobe()`](rmbloat/ProbeCache.py:156) returns `None` when ffprobe finds no video stream. [`batch_get_or_probe()`](rmbloat/ProbeCache.py:555) stores that `None` in results. [`create_video_file_list()`](rmbloat/rmbloat.py:477) wraps it in `PathProbePair(file_path, None)`, and [`main_loop()`](rmbloat/rmbloat.py:694) immediately sorts by `vid.probe.bloat`, raising `AttributeError`. Reproduced with an audio-only `.mp4`: `results: {'audio_only.mp4': None}`. Immediate file arguments are also not extension/existence-filtered in [`get_candidate_video_files()`](rmbloat/ConvertUtils.py:128), so `rmbloat notes.txt` or a deleted saved default path hits the same failure.

### C5. ✅ Auto mode never stops
`--auto-hr` is documented to “stop cleanly after the specified time limit” ([`README.md:386`](README.md:386)), but:
- [`Converter.__init__()`](rmbloat/rmbloat.py:109) stores `auto_mode_hrs_limit` and it is never read.
- [`print_auto_mode_vitals()`](rmbloat/rmbloat.py:505) is defined but never called.
- [`_manage_queue_and_auto_mode()`](rmbloat/rmbloat.py:288) returns immediately in auto mode when the queue is empty.

Result: an auto run idles forever after the queue drains, and cron/`rmbloatd` maintenance runs never terminate on schedule.

### C6. ✅ `TEMP.` / `ORIG.` / `SAMPLE.` files are not skipped
[`is_valid_video_file()`](rmbloat/ConvertUtils.py:75) checks `filename.startswith(SKIP_PREFIXES)`, but [`get_candidate_video_files()`](rmbloat/ConvertUtils.py:169) passes a full absolute path. An absolute path never starts with `TEMP.`, so all three are accepted. Reproduced: a scanned directory returned `good.mkv, ORIG.foo.mkv, SAMPLE.foo.mkv, TEMP.foo.mkv`. This can re-convert backups/leftover temp/sample files and consume large amounts of disk; it combines badly with C7 and the unused temp cleanup.

### C7. ✅ The original-file swap is not atomic and can lose data / overwrite outputs
In [`_execute_file_swap()`](rmbloat/JobHandler.py:706) the original is trashed or permanently unlinked **before** the temp file is renamed into place. If the final [`os.rename()`](rmbloat/JobHandler.py:730) fails, the original is already gone. Additionally:
- `os.rename` silently replaces an existing destination on POSIX.
- `send2trash` failure falls back to permanent `os.unlink()` ([`JobHandler.py:720`](rmbloat/JobHandler.py:720)), even when the user requested trash.
- The surrounding `except OSError` ([`JobHandler.py:747`](rmbloat/JobHandler.py:747)) only appends log strings; the caller still treats the job as successful.

This directly contradicts the README’s “Conversions are atomic” claim ([`README.md:664`](README.md:664)).

### C8. ✅ “Insufficient shrink” is recorded as an error, and the shrink guard is not universal
In [`finish_transcode_job()`](rmbloat/JobHandler.py:593):
- The rejection path calls `set_anomaly(..., 'OPT')`, then the later failure branch calls [`set_anomaly(..., 'Err')`](rmbloat/JobHandler.py:618), overwriting `OPT`.
- It sets `vid.doit = 'ERR'`, increments auto-mode error counters, while [`_log_job_final()`](rmbloat/rmbloat.py:335) is still called with the prior `' OK'` report.
- The minimum-shrink check is conditioned on `original_was_allowed`, so files whose original codec is disallowed can be replaced by a **larger** output despite `-m/--min-shrink-pct` (README says “only replaces if new file is 10%+ smaller”, [`README.md:660`](README.md:660)).

# High-severity findings

1. ✅ **Duplicate method definition.** [`start_transcode_job()`](rmbloat/JobHandler.py:339) was defined again at [`JobHandler.py:442`](rmbloat/JobHandler.py:442); the first copy was dead. `pylint --errors-only` confirmed `E0102: method already defined line 339`. The copies had already diverged (subtitle codec/sample start logic), so future fixes could land in the wrong copy. **Resolved** — see the H1 entry under “Resolved findings”.

2. ✅ **Filename purge loop is wrong.** In [`ConvertUtils.standard_name()`](rmbloat/ConvertUtils.py:237), `end` from the sliced search is reused as an offset into the new full string. Only the first match is processed, and subsequent scanning often stops early. Reproduced outputs:
   - `Movie.1080p.x264` → `Movie.x264.1080p.x265.cmf28.recode.mkv`
   - `Show.S01E02.720p.H.264` → `Show.S01E02.H.264.1080p.x265.cmf28.recode.mkv`
   - `Something.xvid.480p.avi` → `Something.480p.avi.1080p.x265.cmf28.recode.mkv`
   This leaves old codec/resolution tokens in names and can duplicate resolution tags. Use `re.sub` or correctly accumulate offsets. **Resolved** — see the H2 entry under “Resolved findings”.

3. ✅ **Probe cache key collision.** [`_get_valid_entry()`](rmbloat/ProbeCache.py:362) keys only on basename + size, and rewrites the stored `folder`. Reproduced with two different files named `same.mp4` of equal size in different folders: looking up the second returned the first file’s cached metadata. This can assign wrong codec/resolution/duration/subtitle info and confuse [`move_entry()`](rmbloat/ProbeCache.py:473). **Resolved** — see the H3 entry under “Resolved findings”.

4. ✅ **Sample mode writes to a hardcoded developer path.** [`start_transcode_job()`](rmbloat/JobHandler.py:457) used `prefix = '/heap/samples/SAMPLE...'` and never created the directory, so `--sample` failed on any normal machine. **Resolved** — see the H4 entry under “Resolved findings”.

5. ✅ **Stdin/TTY reopen closed the new stdin.** In [`create_video_file_list()`](rmbloat/rmbloat.py:486), `sys.stdin.close()` frees fd 0, so `os.open('/dev/tty')` typically returns fd 0 itself; the old code then closed fd 0 again, leaving `sys.stdin` backed by a closed descriptor and breaking piped `-` input after startup. **Resolved** — see the H5 entry under “Resolved findings”.

6. ✅ **Log trimming scrambled chronological order.** [`_trim_log_file()`](rmbloat/StructuredLogger.py:258) sorted by weighted age, kept newest, then `reverse()`d the effective-age order, which is not the timestamp order: old `ERR` lines ended up after newer `OK` lines, and [`get_window_of_entries()`](rmbloat/StructuredLogger.py:490)/[`refresh_window()`](rmbloat/StructuredLogger.py:534) assume chronology. **Resolved** — see the H6 entry under “Resolved findings”.

7. ✅ **Unbounded ffmpeg log capture.** [`run_ffmpeg()`](rmbloat/TranscodeThread.py:124) appended every non-progress stderr line to `info.texts` without limit, and [`_log_job_final()`](rmbloat/rmbloat.py:267) serialized `asdict(vid)` including `runs[*].texts` while clearing only `dumped['texts']`. Corrupt or long-running jobs could therefore exhaust memory and write huge JSON log entries. **Resolved** — see the H7 entry under “Resolved findings”.

8. ✅ **`StructuredLogger.put(..., data=...)` raises `TypeError`.** [`put()`](rmbloat/StructuredLogger.py:386) passed `data=kwargs.get('data')` and also `**kwargs`, duplicating `data`. Verified: `TypeError ... got multiple values for keyword argument 'data'`. **Resolved** — see the H8 entry under “Resolved findings”.

9. **`Job` lacks `is_retry`/`is_software_fallback` defaults.** [`Job.__init__()`](rmbloat/Models.py:89) does not define them, but [`check_job_status()`](rmbloat/JobHandler.py:211) depends on them. It works only because `start_transcode_job()` injects attributes dynamically; any other `Job` construction will raise `AttributeError`.

10. ✅ **Declared Python 3.8 support is false.** `requires-python = ">=3.8"` in [`pyproject.toml:13`](pyproject.toml:13), but built-in generic annotations such as `tuple[bool, str]` are evaluated at import time on 3.8 ([`ConvertUtils.py:183`](rmbloat/ConvertUtils.py:183), [`StructuredLogger.py:431`](rmbloat/StructuredLogger.py:431), [`rmbloat.py:406`](rmbloat/rmbloat.py:406)). [`shutdown(cancel_futures=True)`](rmbloat/ProbeCache.py:578) also requires 3.9. **Resolved** — the floor is now `requires-python = ">=3.11"`, the `3.8`/`3.9`/`3.10` classifiers were replaced with `3.11`/`3.12`/`3.13`, `[tool.ruff] target-version = "py311"` was added, and the `sys.version_info >= (3, 10)` `slots` fallbacks in [`Models.py`](rmbloat/Models.py:16) and [`ProbeCache.py`](rmbloat/ProbeCache.py:21) were replaced with plain `@dataclass(slots=True)`.

11. ✅ **Docker acceleration path never detects 10-bit support and may lack GPU permissions.** `vaapi_supports_10bit` is only set in the system path ([`FfmpegChooser.py:136`](rmbloat/FfmpegChooser.py:136)), so docker-accelerated encodes force `nv12`/8-bit even for 10-bit sources ([`FfmpegChooser.py:729`](rmbloat/FfmpegChooser.py:729)). The acceleration test runs without `--user` ([`FfmpegChooser.py:315`](rmbloat/FfmpegChooser.py:315)), while real encodes use `--user uid:gid` without supplementary render/video groups ([`FfmpegChooser.py:634`](rmbloat/FfmpegChooser.py:634)); the test can pass while real encodes fail. **Resolved** — see the H9 entry under “Resolved findings”.

12. ✅ **Fatal errors exit with status 0.** [`main()`](rmbloat/rmbloat.py:1522) used to catch all `Exception`, print a traceback, and return normally, so `pylint`, cron, systemd, and shell scripts could not distinguish success from a failed initialization. **Resolved** — see the H10 entry under “Resolved findings”.

13. ✅ **Conversions can silently restart after quitting the Convert screen.** [`ConvertScreen.quit_ACTION()`](rmbloat/rmbloat.py:988) pops the screen but leaves `job_handler` set. [`advance_jobs()`](rmbloat/rmbloat.py:343) starts queued jobs whenever the stack is not on Select, so visiting History/Help afterward can resume conversions unintentionally. **Resolved** — see the H11 entry under “Resolved findings”.

14. ✅ **`rmbloatd` checks the wrong lock path.** [`is_daemon_running_anywhere()`](rmbloat/rmbloatd.py:111) hardcoded `/tmp/video_probes.json.lock` while `ProbeCache` used a different directory, so duplicate-instance detection in `rmbloatd start` was ineffective. Both now derive the path from `ProbeCache.default_lock_path()`, which lives in the private XDG cache directory. **Resolved** — see H12 and L8 under “Resolved findings”.

# Medium-severity findings

- ✅ **Probe-cache concurrency races:** worker threads call `_increment_probe_failure()` → `_set_cache()` without `_cache_lock` ([`ProbeCache.py:225`](rmbloat/ProbeCache.py:225), [`ProbeCache.py:342`](rmbloat/ProbeCache.py:342)), while `store()` iterates the same dictionaries. This could lose updates or trigger “dictionary changed size during iteration”. **Resolved** — see the M1 entry under “Resolved findings”.
- ✅ **Uncaught ffprobe metadata conversions:** `int(video_stream.get('width', 0))`, `float(duration)`, and `int(bit_rate)` can raise `TypeError`/`ValueError` for unusual files ([`ProbeCache.py:171`](rmbloat/ProbeCache.py:171)); these exceptions are not handled by the probe error path. **Resolved** — see the M2 entry under “Resolved findings”.
- ✅ **`Vid.descr_str()` assumes a non-`None` description** ([`Models.py:82`](rmbloat/Models.py:82)). A fresh run created by `start_new_run()` with no `descr` raises `TypeError`; verified. **Resolved** — see the M3 entry under “Resolved findings”.
- ✅ **Incomplete recycle-directory exclusion:** only `.Trash*`, `Trash`, and `lost+found` were skipped ([`ConvertUtils.py:156`](rmbloat/ConvertUtils.py:156)). Synology `#recycle`, QNAP `@Recycle`, `.recycle`, and similar stores were not excluded, so deleted media could be converted. **Resolved** — see the “Incomplete recycle-directory exclusion” entry under “Resolved findings”.
- ✅ **Swap errors are swallowed twice:** [`_execute_file_swap()`](rmbloat/JobHandler.py:747) catches `OSError` locally, so `finish_transcode_job()` still reports success and the UI logs `OK` even when the filesystem operation failed.
- ✅ **Non-atomic state writes:** [`PersistentState.save()`](rmbloat/PersistentState.py:64) and [`IniManager.write()`](rmbloat/IniManager.py:150) truncated/rewrote in place; a crash could corrupt `state.json`/`config.ini`. **Resolved** — see the M4 entry under “Resolved findings”.
- ✅ **Predictable temp/copy files:** the probe cache temp path was `cache_path + ".tmp"` ([`ProbeCache.py:408`](rmbloat/ProbeCache.py:408)), and History copy exported to `/tmp/rmbloat-export.txt`. On multi-user systems these were symlink/clobber and privacy risks. **Resolved** — see the M5 entry under “Resolved findings”.
- ✅ **Docker hardening/portability:** `--net=host --ipc=host` and unlabelled bind mounts were unnecessary privilege surface, startup pulled the image implicitly, and the mutable `:latest` tag was used for runs. **Resolved** — see the M6 entry under “Resolved findings”.
- ✅ **Exception-handling gaps in chooser detection:** [`_run_command()`](rmbloat/FfmpegChooser.py:93) caught only timeout/missing-executable, so `PermissionError`/other `OSError` could abort startup; `real_world_tests()` also unlinked any pre-existing `test_<strategy>.mkv` in the video directory, risking deletion of a user file. **Resolved** — see the M7 entry under “Resolved findings”.
- ✅ **Filter inconsistency:** successful rows are stored with a leading space (`' OK'`) by [`advance_jobs()`](rmbloat/rmbloat.py:326), but [`make_lines()`](rmbloat/rmbloat.py:161) tested `doit.startswith('OK')`; the `-DUN` filters therefore did not hide successful conversions. **Resolved** — see the M8 entry under “Resolved findings”.
- ✅ **History search staleness:** when a search is active, newly read entries were not refiltered ([`rmbloat.py:1127`](rmbloat/rmbloat.py:1127)); `filtered_entries` could lag behind the refreshed log window. **Resolved** — see the M9 entry under “Resolved findings”.
- ✅ **Global `os.chdir()` in job startup:** [`start_transcode_job()`](rmbloat/JobHandler.py:445) changed the process-wide CWD and never restored it. It worked only because consumers used matching relative paths. **Resolved** — see the M12 entry under “Resolved findings”.
- ✅ **Companion-file rename scope:** [`bulk_rename()`](rmbloat/FileOps.py:188) used to recurse through every subdirectory and install results with overwriting `os.rename()`. It now recurses only into directories whose names match the old basename (for example `movie.cache/`) and refuses to overwrite existing destinations. **Resolved** — see L9.
- ✅ **Temp-file lifecycle:** [`emergency_cleanup()`](rmbloat/JobHandler.py:33) was never wired to `atexit`/signals, and `TranscodeThread` is a daemon thread ([`TranscodeThread.py:29`](rmbloat/TranscodeThread.py:29)). A crash could leave an ffmpeg child and `TEMP.*` files behind. **Resolved** — see the M10 entry under “Resolved findings”.
- ✅ **CLI boolean semantics are inverted when saved defaults are true:** [`-F/-B/-M/--use-trash`](rmbloat/rmbloat.py:1664) used `store_false` when the saved default was true, so passing the flag flipped the saved setting rather than forcing it. This contradicted the help text and was confusing in scripts. **Resolved** — see the M11 entry under “Resolved findings”.
- **`-L/--logs` still depends on `less`** being installed; it now uses `-R +F` so escape sequences render (C1 fixed).

# Security review

**Positive:** reviewed ffmpeg/ffprobe invocations use argv lists, not `shell=True`. Display/log quoting uses `shlex.quote`. The `rmbloatd` wrapper quotes user-provided arguments with `shlex.quote` before placing them in the tmux command.

**Risks to address:**
- ✅ Predictable shared paths (`/tmp/rmbloat-export.txt`, probe-cache `.tmp` file) were vulnerable to symlink/clobber attacks on multi-user hosts. **Resolved** — see the M5 entry under “Resolved findings”.
- ✅ Automatic Docker image pull was an unrequested network/supply-chain action. **Resolved** — pulls now happen only on an explicit `force_pull` request, and runs use a resolved digest/image ID.
- ✅ `--net=host --ipc=host` and missing SELinux labels in Docker mode increased container escape/privilege exposure. **Resolved** — host namespaces were removed and mounts now carry `:z` (`:ro,z` for ffprobe).
- ✅ The probe cache and logs contain full media paths and ffmpeg output. They now live in private XDG cache/state directories with directories at 0700 and files at 0600. **Resolved** — see L8.
- ✅ Processing untrusted media with ffmpeg/ffprobe is inherently risky. **Resolved (defence in depth)** — see L10 for the container hardening, local protocol/limits sandbox, private per-job output directory, and `--sandbox` selection. The residual risk of an in-process decoder exploit without any available isolation is documented in the README.

## Resolved findings
